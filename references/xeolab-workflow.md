# XeoLab 고객사 표준 업무 절차

이 절차는 기존 SEO·AEO·GEO·LLMO·Naver·콘텐츠·측정 점검 기준과 함께 적용하며 실행 승인 조건이 우선한다.

## 1. 범위와 기준선

고객의 도메인, 목표, 대상 시장·언어, 접근 권한, 진단 범위와 제약을 확인한다. 읽기 전용으로 공개 페이지, 제공된 데이터와 접근이 허용된 도구를 확인하고 수집 시각, URL, 표본, 기간, 환경과 기준선을 기록한다. 접근하지 못한 자료는 미확인으로 표시한다. 민감한 계정 정보는 보고서에 넣지 않는다.

## 2. 진단과 제안

다섯 레인과 콘텐츠 운영을 점검하고 관찰과 추정을 구분한다. 각 발견 사항은 아래 형식으로 보고한다. 중요도는 영향과 범위, 긴급성, 근거의 신뢰도에 따라 판단하고 예상 범위는 파일·페이지·계정 및 대략적인 작업 단위로 설명한다. 불확실한 공수는 추정으로 표시한다.

| 항목 | 기록 내용 |
|---|---|
| 문제점 | 관찰된 현상 및 영향 |
| 근거 | URL·자료·확인 일시, 재현 방법과 미확인 사항 |
| 중요도 | 높음·중간·낮음 및 판단 이유 |
| 개선 방안 | 대안, 기대 효과의 가설과 한계 |
| 예상 작업 범위 | 대상과 변경 내용, 예상 작업 단위 |
| 실행 승인 필요 여부 | 필요 여부, 승인 대기·승인됨과 승인 범위 |
| 후속 측정 지표 | 기준선, 데이터 출처, 측정 시점과 비교 방법 |

## 3. 승인과 실행

사이트·코드 변경, 배포, 콘텐츠 게시·수정·삭제, 외부 서비스 제출, 계정 설정 변경 전에 대상·구체적 작업·영향을 제시하고 사용자의 명시적 승인을 받는다. 진단 또는 초안 요청은 승인이 아니다. 승인 전에는 읽기 전용 진단과 비게시 초안만 제공한다. 승인 범위가 바뀌면 다시 승인받고, 승인 내용과 실행 결과를 기록한다. 비밀정보나 고객 데이터를 외부에 전송할 때도 사전에 대상과 내용을 확인한다.

## 4. 검증과 측정

승인된 작업은 변경 전후와 크롤러 관점 검증 결과를 기록한다. 노출·클릭·색인·AI 인용 등 이용 가능한 지표의 기준선과 데이터 출처, 측정 시점 및 한계를 제시하고 재측정을 제안한다. 측정 결과와 외부 요인을 구분하며 AI 노출·인용, 순위, 매출 증가를 보장하거나 인과관계를 단정하지 않는다.
